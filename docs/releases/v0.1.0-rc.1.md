# Rastreamento RFID HUPAA — v0.1.0-rc.1

Primeira candidata organizada para a demonstração do MVP e preparação do Marco 2
(16/10/2026). `0.1.0` representa o ciclo inicial com contratos sujeitos a evolução;
`rc.1` identifica uma candidata que ainda depende do aceite da demonstração e da
validação física planejada. Não representa homologação hospitalar.

## Conteúdo da candidata

- Ingestão MQTT, auditoria JSONL, normalização por adapter e leituras idempotentes.
- Debounce, passagem, direção, histórico e projeção temporal da última zona.
- API de cadastros, busca, correções, sessões, permissões e auditoria.
- Dashboard, mapas HUPAA/EASY, leituras e simulador visual de laboratório.
- Prioridade estável nas tabelas por estado/presença, seguida de nome e número.
- Configurações em `config/`, dependências em `requirements/`, Docker em `deploy/`.
- README operacional, diagramas separados, docstrings Python e gerador pydoc.
- Material de apoio ao Marco 2 e roteiro de evidência demonstrável.

## Mudanças nos comandos

```bash
python -m pip install -r requirements/lab.txt
python scripts/dev.py
docker compose -f deploy/compose.yaml --env-file config/environments/.env.local --profile local up -d --build --wait
python -m alembic -c config/alembic.ini upgrade head
make -f scripts/Makefile status-local
python -m ruff check --config config/ruff.toml .
```

Perfis locais existentes passam para `config/environments/`; não entram no Git.
Os pacotes Python mantêm seus nomes, as migrations preservam a linha histórica e
o Compose conserva a identidade padrão de recursos para não abandonar volumes
existentes ao mudar o arquivo de pasta. A renomeação remota fica a cargo do autor.

## Validação e limites

Consulte o [registro de validações](../operations/validation.md), o [roteiro de
demonstração](../milestones/marco-2.md) e os [limites da arquitetura](../architecture/system-overview.md).
Os testes sintéticos não substituem o ensaio físico. Não há hospedagem nesta
entrega. O release é preparado como rascunho/pré-lançamento para revisão da candidata.

Resultado da preparação: 1.311 testes Python e 93 subtestes aprovados no Windows,
3 testes TLS adicionais aprovados no Ubuntu 24.04, 63 testes frontend aprovados,
build TypeScript/Vite e Docker aprovados. Pydoc gerado para 107 módulos; cobertura
de docstrings verificada em 1.057 definições de 125 fontes. O ensaio sintético
local registrou 12 leituras e confirmou passagem A→B, histórico e Zona B.

Após o aceite, uma candidata seguinte pode corrigir problemas com `rc.2`; a versão
`v0.1.0` deve apontar para o commit efetivamente aceito. Correções compatíveis
seguintes usam `0.1.x`; mudanças de contrato durante o MVP usam o próximo ciclo
menor, com migration e instruções de atualização quando necessárias.
